订单管理 PRD

客户小程序研发详细需求规格 · V2.0 · 2026-09-08

统一定义迷你仓、迷你箱和商品订单的列表、筛选、详情、状态映射、动态操作、时间线、金额与资产展示，作为各业务模块的客户侧订单主入口。

属性内容
文档编号MP-ORD-01
适用端客户小程序、运营后台、工单小程序及领域服务
范围订单总览、分类和组合筛选、搜索和排序、订单卡片、三类详情、状态聚合、allowedActions、物流/合同/保单/支付资产入口、取消规则、客服上下文。
不在本模块范围各领域内部状态流转、支付渠道收单、合同模板维护和工单执行；订单中心消费这些服务的权威结果。

1 目标与边界

1.1 本期范围

订单总览、分类和组合筛选、搜索和排序、订单卡片、三类详情、状态聚合、allowedActions、物流/合同/保单/支付资产入口、取消规则、客服上下文。

1.2 不在本模块范围

各领域内部状态流转、支付渠道收单、合同模板维护和工单执行；订单中心消费这些服务的权威结果。

1.3 角色与系统责任

角色或系统职责
客户浏览、选择、签约、付款、提交申请、查询进度
客户小程序采集意图并展示服务端状态，不自行决定价格、库存、资格或审批结果
运营后台维护主数据、价格、库存、可操作项、审批、异常处理和人工改派
工单小程序承接送取、验收、搬仓、清仓等线下任务，回传节点、附件和异常
领域服务保存订单、租约、箱体、预约、支付与合同的权威状态并发布事件

3 状态机与准入

状态码客户文案进入条件下一步
CUSTOMER_ACTION待客户处理待签约、待付款、续租待签约展示高优先主按钮
FULFILLING履约中迷你箱首次履约、商品配送、转仓/退租处理中查看进度或物流
ACTIVE服务中迷你仓租用中、迷你箱在仓存放展示租中服务
EXPIRING即将到期仓位到期提醒、迷你箱到期还箱续租或退租
AFTER_SALE售后中退款、退货、异常工单查看售后
COMPLETED已完成服务结束或商品签收完成查看详情/再次购买
CANCELLED已取消订单关闭查看详情

状态码是跨端契约，中文文案不得作为业务判断条件；写操作必须携带聚合版本并处理409冲突。

4.8 迷你仓订单详情：状态流转与操作

领域状态客户文案详情重点允许操作流转与失败处理
LOCKED / PENDING_SIGN待签约仓位锁定倒计时、报价版本、合同摘要SIGN_CONTRACT, CANCEL签署成功→PENDING_PAYMENT；锁定过期→CANCELLED；签署失败停留并可重试
PENDING_PAYMENT待付款应付明细、支付截止、合同已签标识PAY, CANCEL支付发起→PAYMENT_CONFIRMING；取消后释放仓位，已扣款则转退款
PAYMENT_CONFIRMING付款确认中支付渠道、交易号、最近查询时间REFRESH_PAYMENT, CONTACT_SUPPORT回调成功→ACTIVATING；明确失败→PENDING_PAYMENT；未知结果禁止再次支付
ACTIVATING开仓生效中租约、合同、门禁、保单四项生效进度REFRESH, CONTACT_SUPPORT全部成功→ACTIVE；部分失败→EXCEPTION并创建后台补偿任务
ACTIVE租用中门店仓位、租期、下次付款、门禁状态UNLOCK, RENEW, TRANSFER, MOVE_OUT各动作按资格返回；发起变更后详情进入对应子流程且互斥动作隐藏
EXPIRING即将到期剩余天数、续租报价提示、最早退租日RENEW, TRANSFER, MOVE_OUT续租成功→ACTIVE并更新到期日；到期未续→OVERDUE或COMPLETED，按合同策略
RENEWING续租处理中方案版本、补充协议、应付与生效进度SIGN_RENEWAL, PAY_RENEWAL, VIEW_PROGRESS签约→待付款→生效中→ACTIVE；失败停留原租约并展示可恢复动作
TRANSFERRING转仓处理中审批、费用、目标仓锁定、排期、搬仓工单RESUBMIT, PAY_TRANSFER, VIEW_PROGRESS, CANCEL_TRANSFER审批/付款/排期/搬仓逐段推进；验收及门禁切换成功→ACTIVE并替换仓位
MOVING_OUT退租处理中清仓预约、验收证据、结算版本、退款/补款MODIFY_APPOINTMENT, CONFIRM_SETTLEMENT, PAY_BALANCE, VIEW_REFUND验收→结算→退款/补款→COMPLETED；验收前按规则可撤销回ACTIVE
OVERDUE / RESTRICTED逾期或服务受限欠费账期、金额、限制原因、宽限期PAY_ARREARS, CONTACT_SUPPORT清欠成功→ACTIVE/EXPIRING；门禁是否保留由服务端单独返回，不由前端推断
COMPLETED租约已结束结束原因、结算、退款、历史合同与门禁失效时间VIEW_ASSETS, BUY_AGAIN终态；仅允许查看历史或再次下单
CANCELLED / EXCEPTION已取消或处理异常取消原因/退款进度，或异常节点/跟进编号VIEW_REFUND, RETRY, CONTACT_SUPPORT取消为终态；异常按补偿结果回原流程或进入人工处理

4.9 迷你箱订单详情：状态流转与操作

领域状态客户文案详情重点允许操作流转与失败处理
PENDING_SIGN待签约套餐、箱数、地址时段、合同摘要SIGN_CONTRACT, CANCEL签署成功→PENDING_PAYMENT；资料失效要求重新确认订单
PENDING_PAYMENT待付款应付、合同状态、送箱时段保留倒计时PAY, CANCEL支付确认→DELIVERY_SCHEDULING；取消释放时段，已扣款则进入退款
PAYMENT_CONFIRMING付款确认中渠道交易、查询时间、时段保留说明REFRESH_PAYMENT, CONTACT_SUPPORT成功继续首次履约；失败退回待付款；未知结果禁止重复扣款
DELIVERY_SCHEDULING待安排送箱预约地址/时段、箱数、履约单、取消截止VIEW_PROGRESS, RESCHEDULE, CANCEL生成送箱工单→EMPTY_BOX_DELIVERING；超过取消截止不返回CANCEL
EMPTY_BOX_DELIVERING空箱配送中司机脱敏信息、运单、预计到达、实时节点VIEW_LOGISTICS, CONTACT_SERVICE逐箱交付成功→EMPTY_BOX_DELIVERED；缺箱/拒收→EXCEPTION
EMPTY_BOX_DELIVERED空箱已送达已交付箱数、箱号、封条、收箱须知SCHEDULE_COLLECTION至少一箱可收才可预约；提交后→COLLECTION_SCHEDULED
COLLECTION_SCHEDULED已预约收箱取箱地址/时段、待收箱清单、封条确认RESCHEDULE_COLLECTION, CANCEL_COLLECTION, VIEW_PROGRESS到达取箱→FULL_BOX_COLLECTING；截止前可改期/取消
FULL_BOX_COLLECTING满箱取件中逐箱扫码、封条校验、运单与异常VIEW_LOGISTICS, CONTACT_SERVICE全部收取→WAREHOUSE_INSPECTION；部分失败保留未收箱并标记异常
WAREHOUSE_INSPECTION入仓验收中逐箱验收、照片、箱号/封条/库位绑定VIEW_PROGRESS, CONTACT_SUPPORT全部合格→STORED；损坏或封条异常→EXCEPTION待客户/后台确认
STORED在仓存放箱体总数、逐箱库位、租期、运输权益、活动任务RECALL, TERMINATE, VIEW_TRANSPORTS召回选中箱体→RECALL_DELIVERING；退租需覆盖所有未终止箱体
RECALL_DELIVERING取物配送中召回箱体、运单、预计到达；未召回箱仍显示在仓VIEW_LOGISTICS, CONTACT_SERVICE签收→AT_CUSTOMER；拒收/丢损→EXCEPTION，不得覆盖首次履约旅程
AT_CUSTOMER箱体在客户处在客箱体、返仓截止、剩余运输权益SCHEDULE_RETURN, TERMINATE预约返仓→RETURN_SCHEDULED；逾期按后台计费策略生成费用
RETURN_SCHEDULED / RETURNING返仓处理中返仓时段、逐箱清单、工单与运单RESCHEDULE_RETURN, VIEW_LOGISTICS收取→运输→入仓验收→STORED；部分箱失败按箱体保留状态
TERMINATING结束租用处理中最终取物、空箱回收、损坏/缺失、结算与退款CONFIRM_SETTLEMENT, PAY_BALANCE, VIEW_REFUND全部箱体回收且结清→COMPLETED；缺箱/欠费保持处理中
COMPLETED / CANCELLED已结束或已取消结束原因、历史箱号/运单/合同、退款VIEW_ASSETS, BUY_AGAIN终态；取消前已支付时持续显示退款进度
EXCEPTION履约异常异常箱体、节点、证据、处理编号、预计反馈时间RETRY_ALLOWED_ACTION, CONTACT_SUPPORT后台或工单处理后回到原旅程节点；禁止前端直接跳过异常节点

4.10 动作执行契约

动作服务端准入客户端交互成功/失败结果
SIGN_CONTRACT合同有效、锁定/预约未过期打开合同阅读与签名；签署中禁用返回重复提交签署成功刷新详情；失败保留签署任务并显示原因
PAY / PAY_*应付>0、支付窗口有效、无未知支付结果创建或复用支付意图；页面切后台后轮询权威结果成功进入确认/生效；失败可重试；未知只允许刷新
CANCEL / CANCEL_*服务端返回取消动作且未过截止二次确认并展示费用/退款影响；提交原因码释放仓位/时段/任务；已支付进入退款中，失败保留原状态
UNLOCK本人有效租约、门禁正常且动作未过期进入开锁模块执行定位、资格和凭证校验成功追加门禁时间线；拒绝不改变订单状态并返回原因
RENEW / TRANSFER / MOVE_OUT租约有效且无冲突活动申请跳转对应申请页并传 rentalId、orderId、orderVersion创建成功回详情显示子流程；取消或失败恢复原租用状态
SCHEDULE_* / RESCHEDULE_*对象可预约、时段有库存、未过改期截止选时段并返回 quoteVersion；改期展示旧新时段成功替换预约并同步工单；冲突刷新可选时段
RECALL / SCHEDULE_RETURN选中箱体无活动任务且有运输权益/可付费逐箱选择、校验地址时段、展示权益扣减或费用成功创建独立旅程；部分箱体状态独立推进
TERMINATE无冲突召回/返仓，或服务端允许合并展示全部箱体、最终取物和预估结算，确认后提交进入结束租用流程；结清前不得停止计费或解绑箱体
VIEW_LOGISTICS / VIEW_PROGRESS有关联运单、工单或子流程只读打开对应旅程并保留订单返回路径返回详情自动刷新；查看动作不改变业务状态
CONFIRM_SETTLEMENT / PAY_BALANCE结算版本有效且客户待确认/待补款展示费用证据与版本；确认或付款携带 settlementVersion结清后继续终止；版本冲突刷新并要求重新确认
CONTACT_SUPPORT始终可用，严重权限异常除外传订单、状态、最后事件、异常编号和问题类型创建客服上下文，不修改订单；客服处理通过领域事件回写

4.11 详情刷新、并发与跨端回写规则

•

详情初始化并发请求基本信息、时间线和资产；基本信息失败显示整页错误，时间线或资产失败仅局部降级并可单独重试。

•

allowedActions 必须包含 actionId、code、label、style、priority、route、confirmContent、expiresAt、disabledReason 和 actionVersion；客户端只负责展示与提交。

•

同一订单出现多个客户待办时，按付款/签约、到期/违约、预约、一般服务的优先级确定主任务；其余进入‘更多操作’或关联服务卡片。

•

状态变化以领域事件为准；支付回调、工单回传、后台审批到达后递增 orderVersion，并使旧页面写操作返回409。

•

迷你箱的订单状态是箱体与旅程的聚合展示；任何箱体处于异常或在途时，详情必须展示逐箱差异，不能只给一个笼统订单状态。

•

时间线节点必须包含 eventId、journeyId、objectIds、status、occurredAt、operatorType、customerText；内部备注和员工手机号不得下发。

•

从通知、客服或外链进入详情时先校验登录、订单归属和 businessType；无权不可泄露订单是否存在。

•

页面每次重新可见、动作返回、支付回跳及子流程返回均刷新详情；轮询只用于支付确认和短时履约节点，退到后台即停止。

5 业务规则

•

列表默认按‘需客户处理优先、同类按业务进度、再按更新时间倒序’排序；服务端返回 sortKey，客户端不得仅凭中文状态推断。

•

搜索匹配订单号、商品、门店、仓位和服务端提供的 searchableText；输入300毫秒防抖，关键字最长50字符。

•

筛选支持业务类型、聚合状态和下单时间组合；切换业务类型后重置不适用状态，但保留关键词和时间条件。

•

列表使用游标分页，首次20条、后续20条；筛选变化取消旧请求，按 queryVersion 丢弃乱序响应。

•

订单卡片字段固定为业务类型、订单号、标题、描述、状态、风险提示、3项关键指标和动态操作；缺失字段使用‘--’，不得伪造。

•

详情以 orderVersion 做并发控制；从列表进入先显示快照并立即刷新，服务端新版本覆盖缓存。

•

所有按钮完全依据 allowedActions 数组渲染，动作对象包含 code、label、style、route、confirm、expiresAt、disabledReason。客户端不得按状态硬编码越权动作。

•

写操作携带 Idempotency-Key、orderVersion 和 traceId；409刷新详情并提示状态已变化，禁止本地强改状态。

•

迷你箱必须同时展示‘首次履约’和‘召回与取物’旅程，后者不得覆盖前者；箱体状态按 boxId 独立展示。

•

金额区统一展示原价、优惠、服务费、保险、按金、应付、实付、退款和币种；无值不显示该行，但应付/实付必须有。

•

客服入口必须传 orderId、businessType、statusCode、lastEventId 和客户问题预填，不允许客服页固定示例订单。

•

通知深链打开订单前校验登录和订单归属；无权、已删除或迁移订单显示明确错误并提供订单中心入口。

•

离线只允许读取最近缓存且标记更新时间；所有写操作禁止离线排队，以避免恢复网络后重复执行。

10 非功能与安全

•

列表首屏P95不超过2秒，详情P95不超过1.5秒；长流程返回受理结果和异步进度。

•

敏感字段最小化展示，日志脱敏，下载资产使用短时签名URL。

•

所有状态变更记录前后值、操作者、来源端、原因码、时间和traceId。

•

支持简体中文、繁体中文、英文；日期、货币和地址按香港业务规范展示。

12 验收标准

•

AC-01 三类订单数量、列表结果和筛选条件一致，切换分类不会串数据。

•

AC-02 关键词可命中订单号、门店、仓位、箱号或商品名，清空后恢复当前分类全量。

•

AC-03 订单状态变化后，旧页面执行动作收到409并刷新为最新状态。

•

AC-04 服务端移除某个 allowedAction 后，客户端刷新即隐藏对应按钮。

•

AC-05 迷你箱部分召回时，详情同时显示未召回箱体在仓和召回箱体配送中。

•

AC-06 迷你仓待签约订单展示合同和付款主操作；租用中订单展示开锁、续租、转仓、退租。

•

AC-07 待付款订单重复点击支付只复用或安全创建新的支付尝试，不产生重复扣款。

•

AC-08 符合条件的迷你箱取消后释放送箱时段；已付款订单显示退款处理中。

•

AC-09 订单详情所有时间来自服务端并按客户时区显示，原始时间保留UTC。

•

AC-10 接口超时、空列表、无网络、无权限、订单不存在均有独立可恢复页面状态。
